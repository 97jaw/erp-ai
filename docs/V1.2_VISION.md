# PART 1 — AI Model Autonomy

## 1.1 The Core Philosophy Shift

```
OLD MINDSET (v1.0):
  User asks → Match to predefined tool → Return tool output
  If no tool exists → "Not available" or "I cannot help with that"

NEW MINDSET (v1.2):
  User asks → AI thinks → AI decides:
    a) Call existing tool (fast path)
    b) Compose multiple tools to synthesize answer
    c) Use raw SQL / search_odoo to construct missing data
    d) Generate the answer from underlying data
  Never say "not available"
```

## 1.2 The "Trial Balance" Failure Case

**What happened:**
```
User: "Show me the trial balance"
AI:   "Trial Balance is not available right now."
```

**Why it failed:**
We have not yet implemented `get_ai_trial_balance` Odoo method, so the tool returns "not implemented" and the AI surrendered.

**How v1.2 must handle it:**

```
User: "Show me the trial balance"
AI thinking:
  "I don't have a direct trial_balance tool, but I have:
   - search_odoo (can fetch account_move_line records)
   - get_general_ledger (gives account-level totals)

  A trial balance is just:
    SELECT account, SUM(debit), SUM(credit), balance
    FROM account_move_line
    WHERE posted = true AND date BETWEEN ...
    GROUP BY account
    HAVING balance != 0

  I can synthesize this from search_odoo with the right aggregation."

AI action:
  → Calls search_odoo on account.move.line
  → Groups results by account
  → Computes debit/credit/balance
  → Returns synthesized trial balance
  → Marks visualization as "synthesized" so frontend can label it

Response: "Here is your trial balance for April 2026 (computed from underlying data)..."
```

**Implementation:**

```python
@api.model
def ai_sql_aggregate(self, model, filters=None, group_by=None,
                     aggregates=None, having=None, order=None, limit=100):
    """
    Generic aggregation endpoint for AI.
    Uses Odoo's read_group which is safe and indexed.
    """
    Model = self.env[model]

    # Map aggregate field names to Odoo's read_group format
    fields = []
    for agg in aggregates:
        fields.append(f"{agg}:sum")

    results = Model.read_group(
        domain   = filters or [],
        fields   = fields + (group_by or []),
        groupby  = group_by or [],
        limit    = limit,
        orderby  = order,
    )

    # Apply post-aggregation HAVING clause
    if having:
        results = self._apply_having_filter(results, having)

    return {
        "model": model,
        "rows": results,
        "row_count": len(results),
        "synthesized": True,  # Mark as AI-composed
    }
```

### 2.2.3 PDF Generation Flow

```python
def generate_pdf_report(spec: dict) -> str:
    """
    Takes AI-generated spec, returns PDF file path.
    """
    # Step 1: Render each section to HTML
    rendered_sections = []
    for section in spec["sections"]:
        html = render_section(section, theme=spec.get("theme", "light"))
        rendered_sections.append(html)

    # Step 2: Wrap in master template
    full_html = MASTER_TEMPLATE.render(
        title=spec["title"],
        subtitle=spec.get("subtitle"),
        sections=rendered_sections,
        language=spec.get("language", "en"),
        is_rtl=(spec.get("language") == "ar"),
        company="Elrace Cos. & Gen. Cont. CO.",
        theme=spec.get("theme", "light"),
    )

    # Step 3: Render to PDF
    pdf_path = f"/static/reports/{uuid()}.pdf"
    HTML(string=full_html).write_pdf(pdf_path)

    return {
        "pdf_url": f"/reports/{Path(pdf_path).name}",
        "size_bytes": Path(pdf_path).stat().st_size,
        "generated_at": datetime.now().isoformat(),
    }
```

## 3.2 Design Principles

```
✦ NO TRADITIONAL CHROME
  - No fixed header
  - No persistent sidebar
  - No fixed footer
  - No borders, no panels, no dividers

✦ FLOATING ELEMENTS
  - Every UI element appears to float in space
  - Drop shadows suggest depth
  - Slight Y-axis bob (3-5px sine wave, 4s period)
  - Smooth entry/exit transitions

✦ CANVAS CONCEPT
  - Background is infinite cosmic space
  - Messages and visuals "appear" in the space
  - User can scroll up to see history
  - Pinch / scroll to zoom (optional)

✦ CONTEXT-AWARE CHROME
  - Theme toggle only appears on idle (auto-hide)
  - Quick actions appear when input is empty
  - Logo appears as overlay on hover anywhere
```

# PART 4 — Loading & Placeholder System (V0-Style)

## 4.1 The Problem We Are Solving

```
CURRENT: User sends message → Nothing happens for 3 seconds → Suddenly text appears

NEEDED:  User sends message → Immediate feedback:
         - AI thinking indicator
         - Skeleton of expected response type
         - Progress signals
         - Eventually replaced by real content
```

## 4.2 The Three Phases

### Phase 1 — Thinking (0-1s)

```
User sees:
  - Avatar appears with subtle glow
  - 3 bouncing dots (current behavior)
  - Subtitle: "Thinking..." with subtle text animation

Duration: Until first token arrives
```

### Phase 2 — Generating Text (1-3s, while streaming)

```
User sees:
  - Text streams in character by character (current behavior)
  - Cursor blinking at end
  - Below the text: subtle "Preparing visualization..." indicator
```

```
User sees:
  - Skeleton placeholder appears in the visualization slot
  - Based on detected response type:
    - KPI Card → animated skeleton with shimmer
    - Chart → skeleton bars/lines with pulsing
    - Table → skeleton rows
    - PDF Report → page outline with fake text lines

  Skeleton has:
    - Shimmer animation (gradient sweep)
    - "Generating chart..." floating label
    - Progress indication
```

## 4.4 How Claude Signals Upcoming Visualization

The challenge: Skeletons need to know what TYPE of viz is coming.

**Solution: Add early signal in stream:**

```python
# In SYSTEM_PROMPT, add:
"""
EARLY VISUALIZATION SIGNAL:

Before you write your main response, output a brief hint about what kind
of visualization you will include at the end. This helps the UI show
appropriate placeholders. Use this format on the very first line:

<viz-hint>KPI_CARD|BAR_CHART|LINE_CHART|DATA_TABLE|FINANCIAL_REPORT|PDF_REPORT|NONE</viz-hint>

Then continue with your normal response.

Example:
<viz-hint>FINANCIAL_REPORT</viz-hint>

Your profit and loss for April 2026 shows...
"""
```

Frontend parses the `<viz-hint>` tag from the streaming response, then:

```javascript
// As soon as viz-hint is detected:
setVisualizationPlaceholder(vizType);  // Shows skeleton immediately

// When real viz arrives at end:
replacePlaceholderWithViz(actualViz);  // Smooth transition
```

